# child-mobile-first-ui Specification

## Purpose
定义孩子端移动优先自适应架构与明亮糖果色童趣视觉风格的设计契约，以及重构中 MUST 保持的业务行为不变量，确保孩子端在平板、手机等移动设备上获得一等体验，PC 端为辅助可用形态。

## Requirements

### Requirement: 移动优先断点与导航架构
孩子端 MUST 采用移动优先自适应架构：宽度 <768px（手机）与 768~1023px（平板）为一等形态，MUST 使用底部 Tab 导航（覆盖首页/任务/奖品/盲盒/兑换）与单列卡片流布局，所有页面 MUST NOT 出现横向滚动，交互触控目标 MUST 不小于 44×44px；宽度 ≥1024px（PC）为辅助形态，内容 MUST 以居中受限宽度呈现（而非将移动布局拉伸为桌面多栏布局），全部功能保持可用。

#### Scenario: 手机宽度访问
- **WHEN** 孩子以 375px 宽设备访问孩子端任一主页面
- **THEN** 页面呈现底部 Tab 导航与单列卡片流，无横向滚动，按钮与可点区域不小于 44px

#### Scenario: 平板宽度访问
- **WHEN** 孩子以 768~834px 宽设备访问孩子端
- **THEN** 布局保持移动优先形态（底部 Tab、卡片流），内容宽度适配屏幕且留白均衡

#### Scenario: PC 宽度访问
- **WHEN** 以 ≥1024px 宽访问孩子端
- **THEN** 内容居中于受限宽度列内，导航与全部功能可用，不出现为桌面重排的多栏布局

### Requirement: 明亮糖果色童趣设计系统
孩子端 MUST 落实明亮糖果色设计系统：天空蓝系主色，蜜桃橙、薄荷绿、柠檬黄为功能点缀色；组件圆角 16~20px；正文字号与字重偏大、字体栈以系统圆体风格无衬线为主（MUST NOT 引入第三方字体文件）；以 emoji/贴纸风元素作为装饰点缀。自绘童趣组件层 MUST 覆盖：底部 Tab 导航、大圆角卡片、大触控按钮、Chip 筛选器、空态插画位（emoji 呈现）等；仅允许保留极少量 antd 底层组件（如 Modal、message、Spin）。

#### Scenario: 设计 token 一致
- **WHEN** 检查孩子端各页面与组件
- **THEN** 配色、圆角、字号取自统一设计 token，无页面级硬编码背离

#### Scenario: 筛选器选中态高亮
- **WHEN** 孩子在「我的任务」页查看 Chip 筛选器
- **THEN** 当前选中分类以主题色背景 + 白色文字高亮展示，与未选中项视觉区分明确

### Requirement: 业务行为不变量
孩子端重构 MUST NOT 改变既有业务行为：任务列表分页数据结构（content 字段）、五分类归类规则与默认选中「进行中」、进行中分类内按截止时间升序且未来任务排末尾、未来任务灰色「未开始」标注与禁用提交、提交受限文案「该任务已达最大提交次数」、孩子登录（childId + deviceId）与设备绑定流程、积分余额展示、奖品兑换、盲盒抽取与兑换记录流程。筛选分类 MUST 保持客户端归类，不改变后端列表接口契约。

#### Scenario: 五分类筛选行为保持
- **WHEN** 孩子进入「我的任务」并依次切换五个分类
- **THEN** 归类结果、排序、空态与重构前一致，仅呈现形式变为童趣 Chip 样式

#### Scenario: 提交受限展示保持
- **WHEN** 某任务 canSubmit=false 且 submissionBlockReason 为 MAX_REACHED 或 POINTS_CAP_REACHED
- **THEN** 原提交按钮位置显示「该任务已达最大提交次数」，无可点击提交按钮

#### Scenario: 登录与绑定流程保持
- **WHEN** 孩子经 /child/login 或 /child/bind 完成登录/绑定
- **THEN** 请求参数、成功跳转与失败提示行为与重构前一致
